# LexDesk 参考笔记：模块结构 + 模糊玻璃

- 日期：2026-10-28
- 对象：https://www.ai-lawworkbench.tech/#/ （标题「LexDesk · 法律人的 AI 工作台」）
- 方法：**静态分析前端构建产物**（React + Vite，hash 路由）。证据存档在 `_evidence/`。
- 重要局限：账号 admin 未使用——要渲染登录后的真实页面需要浏览器控制，本会话没有。因此**只看得到"结构与样式"，看不到"登录后的实际界面与交互"**。凡属后者，本文一律不写。

## 1. 模块地图（12 条路由，全部来自前端路由表）

| 路由 | 侧边栏标签 | 我的理解 |
|---|---|---|
| `/` | AI 工作台 | 主入口：一个对话框发起任务 |
| `/tasks` | 我的任务 | 任务列表与状态 |
| `/review` | 审核中心 | **有 `permissions.review` 才渲染**，带未处理数 badge |
| `/cases` | 案件中心 | 案件档案、版本与审核记录、材料归档 |
| `/kb` | 知识库 | 内置法规库（界面写「3.4 万+ 条」）与内部案例 |
| `/assets` | 企业资产 | 被核查对象的资产登记（"登记资产""编辑档案"） |
| `/workspaces` | 工作空间 | 协作容器 |
| `/skills` | 能力中心 | 可管理的技能/模板 |
| `/admin/trials` | 试用申请 | **仅 `permissions.admin`**，带 badge |
| `/account/model` | — | 模型接入 |
| `/account/security` | — | 修改密码 |
| `/login` | — | 登录 |

侧边栏结构（源码原文）：

```
[AI 工作台, 我的任务, (审核中心), 案件中心, 知识库]
[企业资产, 工作空间, 能力中心, (试用申请)]
```

**两段式分组，中间没有分组标题**，靠间距与位置区分：上一段是「今天要干的活」，下一段是「长期积累的资产与平台能力」。这是个便宜但有效的做法——不加视觉噪音就能表达层级。

---

## 2. 值得抄的六个点

### 2.1 侧边栏两段式（工作区 / 资产区）

上游是"任务流"，下游是"资产库"。LawLens 现在把项目、材料、规则库平铺，缺这层区分。

### 2.2 审核中心是一等公民

`/review` 不是设置里的一个子页，而是主导航项，且**只有有审核权限的人才出现**，还带待办数 badge。这正好对上 `DESIGN-v0.1.md` §14 的"律师复核闸门"——闸门现在在 UI 上没有位置，只有流程里的状态。

### 2.3 案件中心 / 工作空间 分离

案件（case）= 可归档、可版本化的交付物；工作空间（workspace）= 协作与素材的容器。两者不是同一层。LawLens 的 `projects` 表目前一个实体同时承担了这两种角色。

### 2.4 企业资产做成实体

`/assets` 是独立模块，有"登记资产""编辑档案""素材归档"——同一个被查企业跨多次核查复用，不必每次重新录入。这直接对应 LawLens 里"同一材料在多个项目重复上传"的浪费。

### 2.5 能力中心（skills）

把"技能"变成用户可管理的对象，而不是写死在代码里的四个 agent。LawLens 的 A/B/C/D 四个 agent 目前是硬编码流水线。

### 2.6 账号设置拆成两个页

`/account/model` 与 `/account/security` 分开。LawLens 现在塞在一个 `/app/settings` 里，混了"我的密钥"和"我的密码"两件安全等级完全不同的事。

## 3. 模糊玻璃：精确配方

### 3.1 前提：有东西可透

页面背景不是纯色，是四层叠加的固定渐变（`--canvas-bg`）。没有这层底，玻璃只会透出一片死白。

```css
/* light */
--canvas-bg:
  radial-gradient(52vw 48vh at 96% -6%, #84b2ea9e, transparent 72%) fixed,
  radial-gradient(40vw 56vh at -4% 40%, #a4c6f08c, transparent 72%) fixed,
  radial-gradient(60vw 52vh at 66% 108%, #92bcee8c, transparent 72%) fixed,
  linear-gradient(180deg, #e4ecf6 0%, #f1f5fa 46%, #e6edf6 100%) fixed;
```

深色主题是同一结构的深蓝版本（`#161a1f` 系）。

### 3.2 令牌

| 令牌 | light | dark | 用途 |
|---|---|---|---|
| `--material` | `#fafcfdd1` | `#2a2e34f7` / `#1b1f24db` | 浮层底（高不透明度，不是"清白"） |
| `--glass` | `#ffffff80` | `#ffffff0b` | 淡玻璃 |
| `--glass-strong` | `#ffffffd6` | `#1b1f24f0` | 强玻璃（登录卡片等） |
| `--surface` | `#ffffff80` | `#ffffff0a` | 卡片底 |
| `--glass-line` | `transparent` | `transparent` | **无描边** |
| `--shadow-lift` | `0 8px 20px -8px #141e3033, 0 28px 64px -18px #141e3057` | `0 8px 20px -8px #00000080, 0 28px 64px -18px #000000b3` | 浮层投影 |

注意两点：
1. **`--material` 不透明度高达 0.82–0.97**。玻璃感不靠"透"，靠"边缘散射 + 大投影"。
2. **`--glass-line: transparent`**——不描边，靠投影和模糊区分层级。这是它看起来干净而不少年感的关键。

### 3.3 四条实际规则（原文摘录）

| 场景 | 配方 |
|---|---|
| 顶栏 | `background: color-mix(in srgb, var(--surface) 84%, transparent)` + `backdrop-filter: saturate(160%) blur(16px)` |
| 菜单/弹层 | `background: var(--material)` + `blur(24px) saturate(160%)` + `1px solid var(--glass-line)` + `--shadow-lift` + `radius 18px` |
| 对话框 | `blur(30px) saturate(160%)` + `radius 26px` + `--shadow-lift` |
| 遮罩 | `backdrop-filter: blur(4px)` + `background: #14171b57` |

全站出现频率最高的是 **`blur(24px) saturate(170%)`**（7 条规则），其次 `blur(24px) saturate(160%)`（3 条）。模糊半径集中在 22–24px，饱和度 160–170%。

**`saturate()` 是灵魂**：只加 blur 会发灰变脏，加饱和才透亮。这一条值得直接抄。

### 3.4 性能纪律（这条最值得抄）

全站共 **28 条 `backdrop-filter` 规则**（计 56 条声明，`-webkit-` 前缀与标准各一半），其中 **16 条开启、12 条显式写成 `none`**。关掉的集中在 `.sheet` 长文区、`.detail__side` 侧栏、`.workpanel` 列表内：

```css
.sheet .card, .sheet .ws-card, .sheet .xp-group, … { backdrop-filter: none }
```

即：**玻璃给浮层（顶栏、菜单、对话框、遮罩），进入滚动容器/长文阅读区就关**。滚动区叠玻璃是掉帧主因，他们显然是有意识地关。

（初稿曾写成"13 处命中、11 处关闭"，是把 `-webkit-` 与标准声明混算的结果；此处的 28/16/12 由正则逐条统计得出。）

### 3.5 其它可抄的尺度

- 圆角：`10 / 16 / 24 / 28 / pill`
- 间距：`4 / 8 / 12 / 16 / 24 / 32`
- 字号：标题 36、数字 30、卡片 16、正文 14、标签 12
- 动效：`cubic-bezier(.2,.8,.2,1)`，`0.42s`（统一变量 `--ipw-ease` / `--ipw-dur`）

### 3.6 语义色三档

每个语义色都有 base / soft / ink 三档，例如：

```
--rose: #e9a197  --rose-soft: #f8e1dd  --rose-ink: #a13a2f
--sage: #93c9a3  --sage-soft: #dff1e4  --sage-ink: #2c6a41
```

低饱和 base 做面、soft 做底、ink 做字。比"红/绿各一个值"耐用得多，尤其适合 LawLens 的风险等级。

## 4. 对 LawLens 的落地建议

| 优先级 | 建议 | 依据 | 工作量 |
|---|---|---|---|
| P0 | 风险等级改用三档语义色（base/soft/ink），不用纯红绿 | §3.6 | 小 |
| P0 | 浮层用玻璃（菜单/对话框/复核单），内容卡片保持实底 | §3.3 + §3.4，且与 `DESIGN-v0.1.md` §12「藏锋」一致 | 小 |
| P1 | 侧边栏两段式：核查流程 / 资产与规则 | §2.1 | 中 |
| P1 | 审核中心提到主导航，带待办 badge，按权限渲染 | §2.2，对应 §14 复核闸门 | 中 |
| P2 | 账号设置拆成「模型接入」「安全」两页 | §2.6 | 小 |
| P2 | 被查企业做成实体，跨项目复用材料 | §2.4 | 大（动数据模型） |

**与「藏锋」的冲突要明说**：LexDesk 的全站渐变画布 + 玻璃，是"轻、亮、消费级"的气质；`DESIGN-v0.1.md` §12 要的是"隐忍、含蓄"。两者不冲突的部分是**浮层玻璃**（对话框、复核单、命令面板），冲突的是**内容区玻璃与彩色画布**。建议只取前者。

---

## 5. 不建议照搬

1. **全站渐变画布**：法律产品的观感会被拉向"AI 玩具"；而且大面积渐变 + 玻璃在低端笔记本上掉帧。
2. **品牌色 `#dcf55a`（荧光黄绿）**：拿来做点缀还行，做主色会与"不出法律意见"的克制定位打架。
3. **12 条路由的模块密度**：v0.1 只有三个板块，抄这个密度会做出一堆空壳入口——正好违反 §2 里"不做假入口"的自我要求。
4. **能力中心（skills）**：在四个 agent 的职责还没稳定前做"技能管理"，是给未定型的抽象加壳。
