# LawLens 产品说明

> 一句话：把港股上市前的法律尽调，从「人翻材料」变成「机器逐页核对 + 律师复核」，每条结论都能回到原文第几页。

- 版本：同事交付版（2026-10-28）+ 字体补丁
- 定位：机器辅助整理，**不构成法律意见**
- 用途：拟赴港上市企业的内部法务与中介团队，做材料自查与整改跟踪

---

## 一、这个产品解决什么问题

拟赴港上市前，企业要交出一批尽调材料：不动产权证、租赁合同、社保明细、劳务派遣协议、章程、增资协议、代持说明、对赌条款……几十份到上百份，每份几十页。传统做法是律师逐份读、逐条摘、手写风险清单，然后反复确认「这条结论的出处在哪一页」。

四个具体痛点：

| 痛点 | 后果 |
|---|---|
| 材料多、页数多 | 读不完，靠抽样，容易漏 |
| 结论与原文脱节 | 报告写「存在抵押」，但没人能立刻说出第几页、哪句话 |
| 结论不可复现 | 换个律师看，结论不一样；客户追问时无法复原推理链 |
| 上市规则条文分散 | 3,000 多条规则，不知道哪条对应哪个风险点 |

## 二、它是怎么做的

### 2.1 主流程

```
上传材料
  └─ 解析：PDF 抽文字层 → 抽不到才 OCR（本地引擎）；保留 [[PAGE n]] 页码锚点
      └─ 三维度依次核查（资产权属 → 劳动用工 → 投资退出与股权）
          ├─ A 意图识别：按维度生成核查要点
          ├─ 缺料检查：材料不全 → 跳过该维度并记录缺口
          ├─ B 资料抽取：逐份抽取字段，强制字段名，附页码与原文
          ├─ C 风险分析：按规则判读等级
          └─ D 质检：逐条回原文核对锚点，定位不到判不合格
      └─ 港股专项材料检查（审计报告、发行方案、股权结构…）
      └─ 生成 docx + PDF 报告
      └─ 触发复核闸门 → 待律师复核
```

### 2.2 四个关键设计

**① 锚点强制**
抽取阶段就要求模型输出「字段 + 取值 + 页码 + 原文片段」，而不是先给结论再去找证据。质检再回原文定位一遍，定位不到的结论不参与输出。

**② 判读用规则，不用模型**
模型只做「抽取」（把材料读成结构化字段）；风险等级由 `agents.py` 的规则计算。原因：模型判读不稳定、不可复现、不可解释。规则的好处是同一份材料永远得到同一结论。

**③ 上市规则内置**
随包携带港交所《主板上市规则》与《GEM 规则》**3,137 条**（主板 1,641 / GEM 1,496，54 个章节），可按条号取原文与页码，结论后附「评估落点」。

**④ 量化评分卡**
五维度 26 个条目：资产 20 / 劳动 20 / 股权 25 / 治理 20 / 资料 10 分。扣分按风险等级系数累加，**没做过的核查记 N/A 不进分母**，覆盖率低于 80% 不给等级——避免用局部核查冒充整体结论。

### 2.3 复核闸门

命中以下任一条件即转「待律师复核」，不直接出结论：

- 结论缺规范依据（规则库 `rule_ref` 为空时必然触发）
- 存在高风险结论
- 同一字段在不同材料中取值冲突
- 金额/口径待确认

## 三、产出什么

| 产出 | 内容 |
|---|---|
| docx 报告 | 逐项事实、证据（文件 + 页码 + 原文）、整改建议、评估落点、所引条文附录 |
| PDF 报告 | 同上，内置中文字体排版，可直接交付 |
| 评分卡 | 五维度得分、覆盖率、等级（覆盖率不足时不给等级） |
| 复核单 | 触发闸门的具体理由，逐条列给律师 |

## 四、价值在哪

**对律师**：不用自己翻页找证据。每条结论点开就是原文，复核从「重做一遍」变成「抽查 + 判断」。

**对企业法务**：自查有清单、有等级、有整改建议，知道申报前要先解决哪几件事。

**对中介**：报告口径统一，客户问「为什么说这是高风险」时有据可查。

四句话概括：

1. **可复核** —— 每条结论都能回到「哪份文件、第几页、哪句话」
2. **可复现** —— 同一份材料跑两次，结论一致（判读是规则不是模型）
3. **可量化** —— 五维度打分 + 覆盖率，能跨项目比较、能跟踪整改进度
4. **可追溯** —— 谁在什么时候改了什么，全部落审计日志

## 五、实测数据

以下均为本项目实测，条件是「14 份虚构脱敏材料 + 真模型（DeepSeek）」：

| 指标 | 结果 | 条件 |
|---|---|---|
| 单次核查耗时 | **65.2 秒** | 14 份 PDF，真模型 |
| 抽取调用 | 89 项，全部 `source=llm` | 无一条走正则兜底 |
| 输出结论 | 14 条，41 个锚点 | 高 8 / 中 6 |
| 评分 | 17.6 / 71（覆盖率 75%） | 未给等级（覆盖率 < 80%） |
| 锚定率 | 100%（312/312 条结论） | 51 个项目，**虚构材料** |
| 溯源率 | 100%（387/387 个锚点可回原文） | 同上，页码一致 99.2% |
| 埋点检出 | 12 / 12 | 脱敏样例内置 12 个埋点 |

**这些数字的边界**：样本是虚构材料，字符串匹配容易命中；真实扫描件受 OCR 噪声影响，溯源率必然下降。目前**没有真实材料的测量结果**，不做对外承诺。

## 六、边界与限制（必须对客户说明）

1. **不构成法律意见**，结论须经律师复核。
2. **判读层是规则**，规则依赖字段名；抽取跑偏会漏判。
3. **条文索引来自 PDF 版面识别**，未与港交所网页逐条比对；仅 8.04 / 8.05 / 8.08 / 14A.01 已核到页码。
4. **单份材料超 12,000 字会被截断**，且报告不提示（当前缺陷）。
5. **单租户**，多客户共用一台会串数据。
6. **OCR 依赖 Python < 3.13**，高版本需用精简依赖（扫描件不可识别）。

## 七、技术与部署

- 后端 FastAPI + SQLite，前端 React + Vite（构建产物由后端托管）
- 本地 OCR（rapidocr），不联网；只有「抽取」一步会把正文发给模型服务商
- 三种交付形态：桌面免安装包（198 MB，双击即用）/ 试用包（需 Python）/ Docker 部署
- 数据全部落在本机 `backend/data/`，删目录即清空
