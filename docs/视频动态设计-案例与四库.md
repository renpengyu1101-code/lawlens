# 案例段落 · Agent × 库 动态设计

> 用户要求：跑案例时让四个 Agent 与四个库"参与进来"，看得见它们在干活；质检要贯穿全程并演示"抓错—退回—改对"；上市监控要有一个虚构新闻被抓取入库的演示。
> 本文只做设计，不出片。

---

## 一、时间点怎么放（结论）

**核心判断：把原 04 章（Agent 介绍）与 05 章（案例）合并成一章。** 因为"介绍 Agent"和"看 Agent 干活"是同一件事，分开讲会重复 30 秒。

| 章 | 原 v7.1 | v8 建议 | 变化 |
|---|---|---|---|
| 01 定位 | 20s | 20s | — |
| 02 痛点 | 35s | 35s | — |
| 03 八步工作流 | 60s | **50s** | 压掉 10s（流程只需点到） |
| 04 Agent 分工 | 47s | **删除，并入 05** | −47s |
| 05 案例实战 | 60s | **100s** | +40s，成为全片重心 |
| 06 四个库 | 56s | **75s** | +19s，加"监控 demo" |
| 07 工程与努力 | 44s | **35s** | −9s |
| 08 边界收尾 | 28s | **25s** | −3s |
| 合计 | 360s | **360s** | 不变 |

**为什么案例要占 100 秒（全片 28%）**：这是唯一能证明"它真的在跑"的段落。其余七章都是"讲"，只有这一章是"看"。

**监控 demo 放在 06 章第四个库的位置**：讲完公共库→企业库→转换库，正好讲"第四个库怎么喂数据"，新闻抓取就是它的输入来源。

## 二、六个动态段落（分镜级设计）

### D1 · 语言识别：从对话框接话（12 秒）

| 时间 | 画面 | 动态 |
|---|---|---|
| 0–3s | 真实工作台，输入框 | 逐字打出「评估我们公司港股上市可能性」 |
| 3–5s | 输入框右侧浮出小圆点 | 圆点（Agent 徽标）弹出，句子被"吸入"成一条金色光带 |
| 5–9s | 光带飞到右栏，展开 | 光带裂成三列：维度 / 要点 / 所需材料 |
| 9–12s | 三列展开成 21 个小格 | 每格 0.1s 依次点亮 |

**视觉语法**：输入（灰）→ 光带（金）→ 结构（墨色卡片）。
**关键细节**：句子里的「港股上市」四个字先高亮，再变成任务单标题——让观众看到"这句话被理解了"。

### D2 · 资料 Agent：扫描 + 调公共库（18 秒）

| 时间 | 画面 | 动态 |
|---|---|---|
| 0–4s | 14 份材料网格 | 一条金色扫描线逐份扫过（每份 0.28s） |
| 4–10s | 扫描过的材料右侧冒出字段碎片 | 碎片（值 + 页码）飞入中央"字段池"，计数 0 → 89 |
| 10–15s | 底部拉开「公共资料库」抽屉 | 抽屉里飞出条文标签（"权属核验·不动产登记"），贴到字段上 |
| 15–18s | 两条冲突字段并排变红 | 486 人 vs 412 人，红框 + 「冲突 1 组」计数 |

**视觉语法**：扫描线（金）→ 字段（白卡）→ 库标签（墨底金边）。
**强调**：字段池的计数器是关键道具，全片出现 3 次（89 项 / 14 条 / 41 锚点）。

### D3 · 分析 Agent：双库注入，疯狂计算（18 秒）

| 时间 | 画面 | 动态 |
|---|---|---|
| 0–4s | 中央"计算核"（同心圆，缓慢旋转） | 左侧公共库、右侧企业库各拉出一条数据流 |
| 4–10s | 数据流以粒子形式注入核内 | 粒子密度递增，核转速加快；核旁数字快速跳动（风险分 0 → 76） |
| 10–14s | 核外环弹出命中卡片 | 「命中 EQT-02 存在股权代持」逐张弹出，每次弹出伴随一次轻微震动（2px） |
| 14–18s | 转速回落，输出 14 张结论卡 | 卡片从核底喷出、排成两列 |

**视觉语法**：粒子（金）+ 计算核（墨环）+ 输出（白卡）。
**关键细节**：中段要有一次"加速感"——转速从 1 倍到 2.5 倍，只持续 2 秒，然后回落。这是"疯狂计算"的全部表达，过长会显得假。

### D4 · 质检 Agent：全片在线 + 抓错退回（14 秒，重点）

| 时间 | 画面 | 动态 |
|---|---|---|
| 贯穿 0–48s | 画面右上角常驻小窗 | 「质检 · 已核 3 / 14」计数随流程推进 |
| 0–5s | 质检灯扫过 14 张结论卡 | 绿勾逐张亮起 |
| 5–8s | 第 7 张亮红灯 | 卡片边框转红、抖动 2px、「页码不符」标签弹出 |
| 8–11s | 卡片被**退回**飞行 | 沿一条红色虚线飞回资料 Agent 的字段池，池子闪烁一次 |
| 11–14s | 重新抽取 → 复检 | 卡片带着新页码飞回，翻绿，计数 14/14 |

**视觉语法**：红 = 不合格，绿 = 通过，红色虚线 = 退回路径。
**这是全片最重要的一镜**：它证明系统会自己发现错误，而不是"什么都对"。
**素材来源**：用我们真实遇到过的"质押误报"（材料写"未见质押"被误判为"存在质押"）作为退回案例——真实发生过，不是编的。

### D5 · 上市监控：虚构新闻被抓取入库（20 秒，06 章内）

| 时间 | 画面 | 动态 |
|---|---|---|
| 0–5s | 一个"新闻网页"（虚构站名 `示例财经`） | 标题「宏昌科技（示例）被曝重大质量诉讼，港交所启动退市程序」 |
| 5–11s | 扫描框从标题移到正文、日期、来源 | 每段被框住 0.8s，右侧同步抽出字段 |
| 11–15s | 抽出结果卡：公司 / 风险类型 / 日期 / 来源 | 四行依次落位 |
| 15–20s | 结果卡飞入「公共资料库 · 负面清单」抽屉 | 计数 18 → 19；同时企业库里「宏昌科技（示例）」卡片状态变红 |

**必须标注**：画面左上角常驻 `示意 · 功能规划中`，公司名带"（示例）"。
**合规红线**：不得使用任何真实上市公司名称、真实新闻标题、真实媒体 logo。

### D6 · 协同总图：连线跑起来（15 秒，06 章末）

| 时间 | 画面 | 动态 |
|---|---|---|
| 0–5s | 四 Agent 四库的静态图（已有 26 秒版） | 连线先画出 |
| 5–11s | 连线上出现流动粒子 | 方向：库 → Agent（取数）为金色，Agent → 库（写回）为墨色 |
| 11–15s | 抽出一条线放大演示 | 分析 → 公共库这条线加粗，旁注「同一条依据，两次核对」 |

## 三、统一视觉语法（六个段落共用）

| 元素 | 规则 |
|---|---|
| 颜色 | 金 `#9a6425` = 数据流动 / 正向；红 `#a8402f` = 不合格 / 退回；墨 `#17181a` = 结构 / 写回 |
| 时间单位 | 每个动作 0.5–0.8 秒；连续动作间隔 ≥0.3 秒 |
| 粒子 | 只在 D3、D6 用，密度 ≤120 个，避免糊 |
| 数字 | 每次都从 0 滚到目标（1.2s），不直接跳 |
| 震动 | 全片只用 3 次，每次 2px、2 帧 |
| 慢动作 | 只在 D4 退回时用 0.5 倍速，持续 0.6 秒 |

## 四、对素材与工作量的影响

| 段落 | 新增素材 | 工作量 |
|---|---|---|
| D1 | 无需新截图（用现有工作台） | 中（光带形变要调） |
| D2 | 无需新截图（材料名已有） | 中 |
| D3 | 无需新截图（纯图形） | 高（粒子 + 环形布局） |
| D4 | 无需新截图（结论卡已有） | 中（退回路径动画） |
| D5 | **要画一个虚构新闻页**（HTML 或 Figma） | 高（新页面 + 抓取框动画） |
| D6 | 复用现有 26 秒动画 | 低 |

**总计新增约 2.5 天**（不含 D5 的新闻页设计）。

---

## 五、三条必须守住的红线

1. **D5 全部虚构**：站名、公司名、标题、日期都要明显是示例；画面常驻「示意 · 功能规划中」。**一旦被当成真实退市事件，就是对外发布虚假信息。**
2. **D4 的"错误"必须是真实发生过的**：用质押误报那一例，字幕可写「真实案例：系统曾把'未见质押'判为'存在质押'，质检拦截」。
3. **D3 的"疯狂计算"不能吹**：转速加速只有 2 秒，不配"每秒百万次"这类无依据的夸张字幕。

## 六、我的建议

**先做 D1 + D4 两个**（26 秒），因为它们最能看到"Agent 在干活"和"质检能抓错"，而且不依赖新素材。

D5（监控 demo）建议放在最后做——它需要先画一个虚构新闻页，且要确认这个能力对外怎么表述（"规划中"还是"已支持"）。
