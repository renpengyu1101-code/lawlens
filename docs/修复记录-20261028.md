## 一、P0：会导致功能不可用或结果错误

### 1. 未填主体的项目必然在报告步骤崩溃

- **现象**：三维度跑完，出报告时抛 `evaluate.<locals>.add() missing 1 required positional argument: 'evidence'`，项目转 `failed`。
- **根因**：`review.add()` 需要 4 个参数，B2 分支只传了 3 个（缺 `evidence`）；触发条件是 `subject_name` 为空——**这是既有缺陷，单板块时代同样会崩**。
- **修法**：给 B2 补 evidence 列表。
- **位置**：`backend/app/review.py` B2 分支。
- **验证**：三维度测试中 `task_runs` 的 error 行原文；修复后同场景通过。

### 2. 某维度缺料时整个项目崩溃

- **现象**：资产维度跑完后，劳动维度缺料，流水线抛 `KeyError: 'type'`，整项失败。
- **根因**：`check_missing()` 返回的键是 `material`，编排层却读 `m["type"]`。
- **修法**：改用 `m["material"]`。
- **位置**：`main.py` 缺料分支。
- **验证**：只上传资产材料跑一遍，劳动/股权正确标记为「材料不全，跳过」。

### 3. 真模型下字段名不受约束，股权维度结论全部丢失

- **现象**：15 份材料跑完，股权维度抽取 34 项却 **0 条结论**；代持材料明明存在。
- **根因**：分析层按固定字段名判定（`field == "存在代持"`），模型自由发挥成「存在股权代持」等写法，规则匹配不到。
- **修法**：新增 `FIELD_VOCAB`（按维度枚举规则层消费的字段）、`FIELD_SYNONYMS`（兜底映射）、`_canonical_field()`（归一化）；抽取提示词强制字段名取自枚举，布尔类字段只在材料明确记载时输出。
- **位置**：`agents.py:215`（词表）、`:302`（归一化）、`_llm_extract` 提示词。
- **验证**：同一套材料 3 条 → **9 条**，股权维度 EQT-02/03/04 全部命中，9/9 带锚点。

### 4. `_num` 只认纯数字，数值型结论静默漏判

- **现象**：LAB-01 合同签订率、LAB-02 社保人数、LAB-03 派遣人数、EQT-01 实缴比例全部不报。
- **根因**：`float("486人")` 抛异常即放弃；模型输出带单位（「486 人」「92.4%」「3,480 万元」），规则模式的正则只产出纯数字。
- **修法**：`_num` 改为正则取数字部分；新增 `_sum` 处理「逐股东列示出资」需要加总的场景。
- **位置**：`agents.py:419`（`_num`）、`:433`（`_sum`）。
- **验证**：脱敏样例 14 条结论（原 9 条），LAB-01/02/03 与 EQT-01 均命中。

### 5. 日期区间解析失败，资质过期漏判

- **现象**：`AST-05 经营资质已过期` 不触发，尽管排污许可证有效期已届满。
- **根因**：`e["value"].split("-")` 只支持 `YYYY-MM-DD`；「2023-06-30 至 2025-06-29」拆出 6 段，`ValueError` 被吞。
- **修法**：新增 `_date_of()`，正则支持 `YYYY-MM-DD` / `YYYY年M月D日` / 区间（取末值为到期日）。
- **位置**：`agents.py:450`。
- **验证**：同一材料复跑，AST-05 命中并带 2 条锚点。

### 6. 进度面板在完成瞬间整块消失

- **现象**：核查刚结束，进度面板消失，「查看结果」点不到。
- **根因**：`CheckProgress` 使用 `onReset` 但未从 props 解构，`{onReset && …}` 抛 `ReferenceError`，React 卸载整棵树。
- **修法**：补 `onReset` 解构。
- **位置**：`frontend/src/components/CheckProgress.jsx`。
- **验证**：CDP 捕获异常栈定位；修复后 14 项断言全过。

## 二、P1：数据错误 / 误判

### 7. EQT-05 假阳性：持股合计变成 105%

- **现象**：章程列 58/12/20/10（合计 100%），却报「股东持股比例合计不等于 100%」，合计 105%。
- **根因**：代持说明里有「其中 5.0% 系代李某持有」，那是某股东持股的**子集**，被当成独立股东加和。
- **修法**：只取「章程 / 股东名册 / 股权结构」类文档求和，并按值去重。
- **位置**：`agents.py` EQT-05 分支。
- **验证**：复跑后 EQT-05 不再误报；14 条结论中无该项。

### 8. 关键材料缺失时 `pymupdf` 未列依赖，扫描件 OCR 必挂

- **现象**：全新环境按 `requirements.txt` 安装后，扫描件 PDF 无法识别。
- **根因**：`parsers._ocr_pdf` 依赖 PyMuPDF 渲染页面，但依赖清单里只有 pypdf。
- **修法**：`requirements.txt` 补 `pymupdf>=1.24`；`requirements-lite.txt` 钉 `pymupdf>=1.24,<2`（2.x 会连带拉 onnxruntime，精简版失去意义）。
- **验证**：在干净虚拟环境安装并解析扫描件成功。

### 9. 条款索引章号误判：估值章的「8.04」被当成上市资格条

- **现象**：索引里 8.04 指向「估值报告」内容，页码 91。
- **根因**：按条号前缀推断章号；规则 PDF 每页首行有「章–页」页码戳（`8–1`、`3A–8`），未利用。
- **修法**：改用页码戳确定当前章号，条号前缀必须与章号一致才收录。
- **位置**：`analysis-library/build_rule_index.py`。
- **验证**：8.04 正确指向 p149「發行人及其業務必須屬於本交易所認為適合上市者」。

### 10. 索引排序崩溃（int 与 str 混比）

- **现象**：`TypeError: '<' not supported between instances of 'str' and 'int'`。
- **根因**：`sort_key` 里数字转 int、字母保留 str，同一元组内混排。
- **修法**：数字补零成等宽字符串后统一比较。
- **验证**：3,137 条正常输出。

### 11. `zhconv.convert` 调用缺 locale，检索整体崩溃

- **现象**：`TypeError: convert() missing 1 required positional argument: 'locale'`，报告生成失败。
- **根因**：直接把需两个参数的函数 alias 成单参数调用。
- **修法**：包一层 `_to_simplified(text)`，固定 `zh-cn`。
- **位置**：`rule_refs.py`。
- **验证**：繁简检索正常；`8.04` 可定位，主题检索可命中。

### 12. 相似案例误标：资质过期被标成「递表与审核周期」

- **现象**：`AST-05 经营资质已过期` 被附上「递表/申请失效」的案例与建议。
- **根因**：单关键词「失效」命中即标注。
- **修法**：改为「≥2 个关键词」或「单个 ≥4 字专有词」才标注；同时补充 `盈利测试`、`保荐人` 等词，修掉收紧后的漏标。
- **位置**：`rule_refs.lookup_similar()`。
- **验证**：8 个场景 5 命中 3 正确无匹配（社保、代持、资质无港规对应，返回空）。

### 13. 发行包内混入测试数据与 `.env`

- **现象**：198 MB 桌面包里出现 `backend/data/app.db`（含测试用户与上传件）和 `.env`。
- **根因**：先在暂存目录内跑自检，产物未清理即打包。
- **修法**：打包前删除 `backend/data`、`.env`；解压校验条目数为 0。
- **验证**：`tar -tf` 检查 `backend/data/` 与 `.env` 条目均为 0。

### 14. 直接 `uvicorn` 启动会静默降级为演示模式

- **现象**：不经 `start.ps1` 启动时，`.env` 不被加载，`mock_mode=true`，抽取走正则（0.0s，`source=regex`），界面上无明显提示。
- **根因**：只有 launcher / start 脚本负责读 `.env`，应用自身不读。
- **修法**：内部排查脚本统一先加载 `.env`；对外启动路径继续走 `start.cmd` / 桌面版 `START.bat`。
- **状态**：**未彻底修复**，见「已知问题」。

## 三、P2：体验与工程

### 15. PowerShell 脚本缺 BOM，中文全部乱码报错

- **现象**：`start.ps1`、`backup.ps1`、`install.ps1`、`publish.ps1`、`make-package.ps1` 在 Windows PowerShell 5.1 下直接语法错误。
- **根因**：UTF-8 无 BOM 被按 GBK 读取。
- **修法**：全部改存 UTF-8 with BOM；`.bat` 内注释改 ASCII。
- **验证**：逐脚本 `Parser::ParseFile` 语法检查 + 实际运行。

### 16. 首次安装脚本返回退出码 1

- **现象**：安装实际成功，但 `install.ps1` 退出码为 1，使用者误判失败。
- **根因**：最后一条原生命令的返回值泄漏为脚本退出码。
- **修法**：末尾显式 `exit 0`。

### 17. 启动器内网地址取到虚拟网卡

- **现象**：打印的内网地址是 `192.168.44.1`（VMware），实际不可达。
- **根因**：取第一个非回环 IPv4。
- **修法**：优先取有默认网关的网卡，取不到再回退。

### 18. 进程重启后项目永远停在「执行中」

- **现象**：服务被杀后，运行中的项目状态不再变化，前端一直转圈。
- **根因**：无启动恢复逻辑。
- **修法**：启动时把 `running` 归位为 `failed`，写一条 error 步骤并退还积分。
- **位置**：`main.py:129`。
- **验证**：构造 `running` 项目后启动，状态转 `failed`，积分 90 → 100，流水 +1。

### 19. 公网发布脚本复用了旧进程，安全开关未生效

- **现象**：`publish.ps1` 起隧道后，`register_open` 仍为 true（自助注册未关闭）。
- **根因**：脚本发现端口已监听就直接复用，而旧进程没有新环境变量。
- **修法**：建隧道前先查 `/api/health`，`register_open=true` 则拒绝发布并提示先停旧进程。
- **验证**：重启后端后 `register_open=false`，注册返回 403，cookie 带 `Secure`。

### 20. 账号菜单头部挤压、背景过透

- **现象**：长邮箱撑破菜单边界；底层页面文字透过菜单。
- **根因**：`.account-id` 缺 `flex:1; min-width:0`；背景 `rgba(255,255,255,.82)` 过透且无 GPU 时 `backdrop-filter` 不生效。
- **修法**：补 flex 收缩；背景提到 `.94` + 描边；菜单宽 248→264。
- **验证**：CDP 取 `getBoundingClientRect` 复核 + 2× 裁图对比。

### 21. nginx 限流指令放在错误上下文

- **现象**：`nginx.conf` 里 `limit_req zone=login` 引用未定义的 zone，`nginx -t` 会失败。
- **根因**：`limit_req_zone` 必须在 `http{}`，不能与 `location` 同级。
- **修法**：改为注释示例，并写明需在上层 `nginx.conf` 的 `http{}` 中先声明。
- **状态**：未实机验证（无 nginx 环境）。

| 变更 | 影响 |

| 单板块 → 三维度（资产/劳动/股权） | 单次核查耗时与 token 约为原来的 3 倍；某维度缺料仅跳过该维度 |
