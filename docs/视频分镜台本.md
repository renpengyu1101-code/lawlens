## 一、参考片拆解（我看到的）

**版式**：固定「左栏 + 右画布」，全片不变。

```

│ NodeCite    │  ① 顶部横条：五个场景，当前高亮  │

│             │  没收钱，也可能被禁售           │
│ 01 02 03 …  │                              │
└─────────────┴──────────────────────────────┘
```

**三种画面类型**（全片反复用）：

| 类型 | 用在 | 特征 |
|---|---|---|
| **信息板** | 讲问题、讲机制 | 左栏条目高亮 + 右画布时间轴 / 列表 / 大标题 + 一句话结论 |
| **录屏模拟** | 讲功能 | 右画布做成产品界面卡片，步骤逐条打勾，右上角细进度条 |
| **片尾** | 收束 | 满屏星点、居中 logo + 中英标语 |

**节奏**：每章约 1 分钟；每章先抛问题（左栏），再给证据（右画布），最后落一句"痛点/结论"（琥珀色大字）。

**色彩**：近黑底 `#080c11`，薄荷绿 `#3ee0c0` 作强调，琥珀 `#f2b13c` 作警示，红 `#ff5c5c` 作负向。

## 四、台本（连续口播稿）

> 语速按 160–170 字/分钟计，全文约 900 字，对应 5'30"

**【0:00】**
你有多久，没逐页读过一份八十页的合同了？

**【0:08】**
一家准备赴港上市的企业，要交十几类材料，几百页。读不完，只能抽样。报告里写了"存在抵押"，可你问他第几页，他得回头翻。换位律师再看，结论又不一样。对律师来说，没有出处的结论，等于没做。

**【0:38】**
LawLens 就干一件事：把问题交给透镜，让每个结论都有出处。

**【0:45】**
上传材料，系统解析并保留页码；按资产权属、劳动用工、投资退出与股权三个维度逐个核查；每条结论回原文质检；最后出三样东西——报告、评分、复核单。

**【1:20】**
凭什么说结论可信？看这条：核心资产权利人不是拟上市主体。证据是不动产权证第 1 页的这句话。质检会把每条引文拿回原文再找一遍，找不到的，不参与输出。所以它能被复核、能复现、也能追溯。

**【2:10】**
核查分三个维度。每一步都会长出来：识别要点、抽取字段、判读风险、回原文质检。某个维度材料不全，只跳过这一枝，不影响其他。十四份材料，全程 65 秒。

**【3:00】**
等级不是感觉，是算出来的。五个维度、26 个条目，命中高风险这一项直接归零，中风险扣六成，低风险扣三成。覆盖率不到 80%，就不给等级——避免用局部核查冒充整体结论。

**【3:50】**
系统内置三千一百三十七条上市规则。每条结论后面，附上它落在哪一条、第几页。缺规范依据、存在高风险、材料互相矛盾——命中任一，转律师复核。律师确认之前，不作为最终结论。

**【4:40】**
实测：十四份材料，65 秒，十四条结论，四十一个锚点，全部可回原文。这组数字来自虚构材料，真实材料会受扫描质量影响，我们不做承诺。接下来要补条文号、用真实材料复测、做多租户隔离。

**【5:22】**
LawLens，让每个结论都有出处。

## 六、与现有 Remotion 工程的关系

现有 `lawlens-video/` 是"整屏六幕"结构（无左栏），与参考片的"左栏 + 右画布"不同。

要做成参考片样式，需要：

1. 新增 `Rail.tsx`：左栏组件（品牌、章节号、提问、条目高亮、底部章节进度）
2. 现有每个场景改为"右画布内容"，宽度从 1920 收到约 1280，左边留 640 给 Rail
3. 章节时长从 60 秒拉到 5'30" 后，总帧数约 9,900 帧，渲染时间约 8–12 分钟

## 七、注意事项

1. **数字一致性**：片中 65.2 秒 / 14 条 / 41 锚点 / 3,137 条，必须与 `docs/产品说明.md` 第五节完全一致；若重跑数据变化，全片统一改，不能只改一处。
2. **不承诺效果**：不得出现"准确率 100%""替代律师"类表述；锚定率/溯源率是"虚构材料下"的测量值，片中不口播这两个比率，只放实测四数。
3. **边界必须出现**：片尾前必须有一屏"不构成法律意见 / 律师确认前不作最终结论"。
4. **参考片版权**：版式可学，素材（图标、星点背景、字体）需自制或使用可商用资源，不得直接截取。
