# LawLens 产品说明 v2

> **一句话**：面向港股上市的 AI 法律尽调平台——四个 Agent 分工跑完一次核查，四个库为每个结论提供依据，每条结论都能回到原文第几页。

- 定位：**港股上市分析平台**（不是通用合同审查，也不是通用法律问答）
- 形态：可私有化部署的 Web 系统 + 桌面免安装版
- 边界：机器辅助整理，**不构成法律意见**，结论须经律师复核

---

## 一、我们到底在做什么

一家企业要赴港上市，先要把自己"翻个底朝天"：土地房产、租赁、知识产权、排污许可、社保、劳务派遣、章程、出资、代持、对赌……十几类材料、几百上千页。律师要逐份读、逐条摘、写风险清单，再回答"这条结论出处在哪一页"。

LawLens 做三件事：

1. **把材料读成结构**——逐页解析，保留页码锚点
2. **把风险判出来**——按港股上市的三条主线（资产、劳动、股权）逐项核查
3. **把结论钉在原文上**——每条结论附「文件 + 页码 + 原文」，并给出对应的上市规则条款

一句话解释我们和通用 AI 的区别：**通用模型给你一段像样的文字，我们给你一条能被律师复核的结论。**

## 二、AI 工作流（8 步）

```
① 用户登录
    ↓
② 提交需求（一句话 + 上传材料）
    ↓
③ 意图识别：把自然语言转成技术语言
    （"我想评估上市可能性" → 三个维度 + 21 项核查要点）
    ↓
④ 任务拆解 + 材料核验
    ├─ 材料齐全 → 继续
    └─ 缺必要材料 → 回传用户，列出缺什么（不硬跑）
    ↓
⑤ 任务分发：按类型派给不同 Agent
    ├─ 语言识别 Agent
    ├─ 资料 Agent
    ├─ 分析 Agent
    └─ 质检 Agent
    ↓
⑥ 结果复核与修改（质检不过 → 退回重抽，最多 2 轮）
    ↓
⑦ 汇总（跨维度去重、冲突归并）
    ↓
⑧ Agent 出具报告（docx / PDF + 评分卡 + 复核单）
```

**关键点**：④ 是一个回路，不是直线——缺料就停下来问，不猜。⑥ 也是一个回路——质检不过就退回，不硬出结论。

## 三、四个 Agent 各干什么

| Agent | 职责 | 输入 | 输出 | 失败时 |
|---|---|---|---|---|
| **① 语言识别** | 识别用户自然语言，拆解为可执行的核查任务 | 用户提问 + 主体信息 | 任务单（维度、核查要点、所需材料清单） | 意图不明 → 回问用户 |
| **② 资料** | 读取上传材料，提取字段，标注来源，检查冲突 | 材料文本（含页码） | 结构化字段（值 + 页码 + 原文） | 材料缺失 → 标记缺口；字段冲突 → 记入冲突组 |
| **③ 分析** | 调用公共资料库，判读风险，给出整改建议 | 结构化字段 + 规则库 | 风险条目（等级 + 事实 + 建议） | 依据不足 → 标「待补」而非编造 |
| **④ 质检** | 核查每条结论是否有依据、数据是否一致、报告与规则是否一致 | 结论 + 原文 + 规则 | 通过 / 不合格 / 材料缺失提示 | 定位不到 → 该条不参与结论 |

**质检的三种查法**：
1. **锚点查**——引文能否在原文定位
2. **数值查**——同一指标在不同材料中是否一致（486 人 vs 412 人）
3. **规则查**——结论是否落在某一条上市规则上；落不上就转复核

## 四、四个库（产品的地基）

| 库 | 内容 | 现状 | 更新 |
|---|---|---|---|
| **① 公共资料库** | 港股上市规则（主板 + GEM **3,137 条**）、香港法例、企业负面清单、失败案例 | 规则 3,137 条已入库；招股书 **98 份**、风险条目 **10,007 条**、命中记录 **3,482 条**、失败材料 **18 份** | **常态化更新**（新增招股书按月入库，规则随港交所修订同步） |
| **② 企业情况库** | 每家企业单独存档：材料、版本、结论、评分、复核记录 | 按企业隔离，支持版本对比 | 每次核查自动入库 |
| **③ 数据采集与自然语言转换库** | 把材料文本转成标准字段的映射规则：同义词表、字段词典、抽取模板 | 三维度字段词表已固化 | 随真实材料反馈迭代 |
| **④ 上市及退市监控** | 递表、聆讯、招股、挂牌、退市节点 | **规划中** | — |

### Agent × 库 的协同（这是产品的核心结构）

```
        ┌──────────── ① 公共资料库 ────────────┐
        │  规则 3,137 条 · 招股书 98 份 · 负面清单   │
        └───────▲───────────────▲──────────────┘
                │ 查条款          │ 查同类案例
        ┌───────┴───────┐  ┌────┴──────────┐
        │ ③ 分析 Agent  │  │ ④ 质检 Agent  │
        └───────▲───────┘  └────┬──────────┘
                │ 结构化字段        │ 回原文核对
        ┌───────┴───────┐  ┌────┴──────────┐
        │ ② 资料 Agent  │◄─┤ ① 语言识别     │
        └───────▲───────┘  └───────────────┘
                │ 读取
        ┌───────┴───────────────────────────┐
        │ ② 企业情况库（按企业隔离、版本留痕）    │
        └───────────────────────────────────┘

        ┌───────┴───────────────────────────┐
        │ ③ 数据采集与自然语言转换库            │
        └───────────────────────────────────┘
```

一句话概括：**Agent 负责"想"，库负责"记"；分析 Agent 从公共库拿依据，质检 Agent 拿同一份依据回查结论，资料 Agent 把结果写回企业库。**

## 五、怎么实现的（四个工程决定）

1. **锚点强制**——抽取阶段就要「值 + 页码 + 原文」，不是先给结论再补证据
2. **判读用规则，不用模型**——模型只做抽取；等级由规则算，保证同一材料两次跑结果一致
3. **规则索引本地化**——3,137 条条文随包发布，断网可用，按条号取原文与页码
4. **复核闸门**——缺依据 / 高风险 / 材料冲突，命中任一即转律师复核，不直接出结论

## 七、实测数据

条件：14 份脱敏材料 + 真模型（DeepSeek），2026-10-28 实测。

| 指标 | 结果 |
|---|---|
| 单次核查耗时 | 65.2 秒 |
| 输出结论 | 14 条，41 个锚点 |
| 抽取来源 | 89 项，全部 `source=llm` |
| 评分 | 折合 18.5 / 95，覆盖度 75%，暂不定级 |
| 埋点检出 | 12 / 12 |

> 样本为虚构脱敏材料，真实材料受扫描质量影响，锚定率与溯源率会下降；目前**没有真实材料测量结果**，不做对外承诺。

## 八、价值

| 谁 | 得到什么 |
|---|---|
| **律师** | 不用翻页找证据，复核从"重做一遍"变成"抽查 + 判断" |
| **企业法务** | 有清单、有等级、有整改建议，知道申报前要先解决哪几件 |
| **中介/保荐人** | 报告口径统一，客户问"为什么是高风险"时能当场翻到原文 |
| **决策层** | 五维评分 + 覆盖率，能横向比较、能跟踪整改进度 |

四句话：**可复核**（回到原文）、**可复现**（同材料同结论）、**可量化**（五维打分）、**可追溯**（审计留痕）。

## 九、边界与限制（必须同时说明）

1. 不构成法律意见，结论须经律师复核
2. 判读层是规则，规则依赖字段名；抽取跑偏会漏判
3. 条文索引来自 PDF 版面识别，仅 8.04 / 8.05 / 8.08 / 14A.01 已核到页码
4. 单份材料超 12,000 字会被截断，报告暂不提示（修复中）
5. 单租户，多客户共用一台会串数据
6. 上市及退市监控尚未实现，属规划

## 十、部署形态

| 形态 | 适用 |
|---|---|
| 桌面免安装包（198 MB，双击即用） | 单人在自己电脑上用 |
| 源码 / 试用包（需 Python 3.11–3.12） | 有技术人员的团队 |
| Docker + nginx + HTTPS | 内网服务器或云主机 |
| 临时公网隧道（Cloudflare） | 临时演示，链接每次变 |

数据全落本机 `backend/data/`，删目录即清空；OCR 本地运行，只有抽取一步会把正文发给模型服务商。
